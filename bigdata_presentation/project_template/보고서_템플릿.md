## 1. 문제 정의
- 무엇을, 왜 분석하는가 : 전 세계 개발자들의 협업 공간인 GitHub의 대용량 로그 데이터(GH Archive)를 분석하여 현대 오픈소스 생태계의 활동 트렌드와 협업 환경의 구조적 특징을 규명하고자 한다.
- 이 데이터로 풀고 싶은 문제 / 예측 대상(target)
: 각 레포지토리의 활동 지표를 바탕으로 해당 프로젝트가 어떤 협업 환경 성향(개발 기여 중심형, 소통 커뮤니티형, 초기/정체형)을 가졌는지 이를 통햐여 취업 준배해야 하는 개발자는 어떻게 나아가는지 GITHUB 데이터를 조사햐였다.

## 2. 데이터 소개 & EDA
데이터 규모(행·열), 형식: ForkEvent, IssuesEvent, PullRequestEvent 등 총 6가지 핵심 깃허브 이벤트별로 샘플링된 수만 건의 CSV 형식 데이터를 활용한다. 공통 컬럼으로 id, type, actor_login, repo_name, created_at 및 상세 JSON 데이터 덩어리인 payload 컬럼으로 구성되어 있다.
실질적으로 많은 시간대의 모든 데이터를 통한 조사를 치루고 싶으나 1일 기준 2GB이상으로 PUSHEVENT가 80% 이상 존재함으로서 가치 있는 EVENT로 많은 시간대 조사하였다.




데이터 규모(행·열), 형식: ForkEvent, IssuesEvent, PullRequestEvent 등 총 6가지 핵심 깃허브 이벤트별로 샘플링된 수만 건의 CSV 형식 데이터를 활용한다. 공통 컬럼으로 id, type, actor_login, repo_name, created_at 및 상세 JSON 데이터 덩어리인 payload 컬럼으로 구성되어 있다.

EDA로 발견한 사실 2~3가지:

글로벌 개발자 활동 시간대 편차: created_at 시계열 데이터를 파싱하여 24시간 단위 활동량을 분석한 결과, 특정 시간대에 이벤트가 급증하는 글로벌 개발자들의 유기적인 활동 사이클 패턴을 발견했다.



상위 쏠림 현상: 특정 유저(Actor)와 일부 대형 레포지토리에 이벤트가 과도하게 집중되는 롱테일(Long-tail) 법칙과 파레토 법칙이 오픈소스 생태계 전반에 강하게 작용하고 있음을 확인했다.
![Issue Open MVP](./bigdata-project/bigdata_presentation/project_template/data/images/issueopenMvP.png)

결측·이상치 처리 방법: raw 데이터에서 결측치가 발생할 수 있는 payload 내부의 가변적 JSON 구조를 안전하게 처리하기 위해 파이썬 예외 처리(try-except) 구문을 도입하여 파싱 오류 및 결측 데이터를 비어있는 딕셔너리({})로 안전하게 대체했다. 또한, 분석 스케일을 맞추기 위해 극단적인 이상치 및 음수 데이터를 Pandas의 clip(lower=0) 함수로 정제했다.
